# Movie Site Stats

## Instructions

### Step 1: Collect the data

Ask the user to provide their site data in one of the following formats:

| Source | What to export or paste |
|--------|------------------------|
| Google Analytics 4 (GA4) | Export the "Ecommerce purchases" or "Events" report as CSV |
| Custom admin dashboard | Export orders table as CSV (UTF-8 or Windows-1255 if Hebrew column headers) |
| Green Invoice / iCount | Export monthly revenue report as CSV |
| Pasted table | Copy-paste rows from the admin panel directly into the chat |

Minimum required fields for a meaningful analysis:

| Field | Hebrew label (common) | Notes |
|-------|----------------------|-------|
| Order date | `תאריך הזמנה` | DD/MM/YYYY or ISO format |
| Movie title | `שם סרט` | Hebrew or Latin |
| Order total (NIS) | `סכום` or `מחיר` | Gross, VAT-inclusive |
| User/customer ID | `מזהה משתמש` | For retention analysis |
| Order status | `סטטוס` | Completed, cancelled, refunded |

If the CSV came from a Hebrew Excel export, warn the user it may be in
Windows-1255 encoding and ask them to re-save as UTF-8 before uploading.

### Step 2: Clean and normalize the data

Before computing any metric:

1. Parse dates. Accept both DD/MM/YYYY (Israeli standard) and YYYY-MM-DD (ISO).
   If a date is ambiguous (e.g., 05/06/2025), ask the user which format is used.
2. Strip currency symbols (ש"ח, NIS, ₪) from amount columns and convert to
   plain numbers.
3. Normalize movie titles: trim whitespace, unify casing for Latin titles,
   preserve Hebrew titles verbatim including sofit letters (ך ם ן ף ץ are
   distinct from כ מ נ פ צ, do not conflate them).
4. Filter out cancelled and refunded orders from revenue totals. Keep them in a
   separate "cancelled" bucket for churn analysis.
5. Confirm VAT rate: current Israeli VAT is 18% (as of January 2025). If the
   user needs net-revenue figures, compute: net = gross / 1.18.

### Step 3: Compute the core metrics

Produce the following metrics in a markdown table:

| Metric | Formula / Logic |
|--------|----------------|
| Total orders | Count of completed orders |
| Total gross revenue (NIS) | Sum of order totals, VAT-inclusive |
| Total net revenue (NIS) | Gross / 1.18 |
| Average order value (AOV) | Gross revenue / total orders |
| Top 10 movies by orders | Group by title, count, sort descending |
| Top 10 movies by revenue | Group by title, sum amount, sort descending |
| Orders per day / week / month | Time-series grouped by the chosen period |
| Cancellation rate | Cancelled orders / total orders |
| Returning customer rate | Users with more than 1 order / total unique users |

If user ID data is available, also compute:

- New vs. returning customers per period
- Average orders per user (lifetime)

### Step 4: Identify trends and anomalies

Scan the time-series for:

- Sudden spikes: a day with 3x the average order volume (could be a promotion
  or a viral movie release).
- Drop-offs: consecutive days with zero or near-zero orders (could indicate a
  site outage or payment issue).
- Seasonal patterns: Israeli holiday periods (Rosh Hashana, Pesach, Sukkot,
  Hannuka) often spike home-entertainment demand. Note if the data covers a
  holiday period.

### Step 5: Present the report

Output a structured markdown report with the following sections:

1. **Summary card** (total orders, gross revenue, net revenue, AOV, date range)
2. **Top movies** table (by orders and by revenue, side by side or stacked)
3. **Time-series view** (monthly or weekly depending on date range)
4. **Retention snapshot** (if user IDs are available)
5. **Anomalies and highlights** (bullets, 3-5 items max)
6. **Recommended next actions** (e.g., promote the top-performing title,
   investigate the cancellation spike on a specific date)

Ask the user whether they want the report in Hebrew or English before generating.

Hebrew report header template (use indented block, not a code fence):

    דוח ביצועי אתר הסרטים
    תקופה: [מתאריך] עד [עד תאריך]
    סה"כ הזמנות: [N]
    הכנסה ברוטו: [X] ש"ח
    הכנסה נטו (לפני מע"מ): [Y] ש"ח
    ממוצע הזמנה: [Z] ש"ח

## Gotchas

- **Date format ambiguity:** Israeli exports use DD/MM/YYYY but some tools
  export MM/DD/YYYY or ISO YYYY-MM-DD. Always confirm with the user before
  computing date ranges or trends. A wrong format shifts every order by months.

- **Windows-1255 encoding:** CSV files exported from Hebrew Excel or older
  Israeli admin systems often use Windows-1255 instead of UTF-8. Hebrew text
  will appear as garbled characters if the wrong encoding is assumed. Ask the
  user to re-save as UTF-8, or detect the encoding before parsing.

- **VAT-inclusive vs. VAT-exclusive amounts:** Israeli invoices typically show
  the gross (VAT-inclusive) amount. If the user's CSV already shows net
  amounts, do not divide by 1.18 again. Confirm which the user has before
  computing net revenue.

- **Sofit letter normalization:** Hebrew movie titles that end in ך ם ן ף ץ
  use sofit (final) forms that are distinct Unicode code points from the
  non-final forms. Do not normalize them to non-sofit when grouping by title,
  or two spellings of the same title may be treated as different movies.

- **Currency labels in the data:** ש"ח, NIS, and ₪ all mean Israeli shekel.
  Strip the label before numeric operations but preserve the label in all
  output. Do not convert to another currency unless the user explicitly asks.

- **Gershayim in Hebrew text:** Abbreviations like ש"ח and מע"מ use the
  gershayim character (״) rather than a straight double-quote. Preserve them
  verbatim when reading or reproducing Hebrew labels from the data.

- **Cancelled orders in revenue totals:** Including cancelled or refunded
  orders inflates gross revenue figures. Always filter them out of revenue
  totals and report the cancellation count and rate separately.

## Troubleshooting

### The movie title column contains garbled Hebrew characters

Cause: the CSV was exported in Windows-1255 encoding but read as UTF-8.
Solution: ask the user to open the file in Excel, go to Save As, select
CSV UTF-8 (with BOM) as the format, and re-upload. Alternatively, if you have
shell access, run `iconv -f windows-1255 -t utf-8 input.csv > output.csv`.

### Revenue totals do not match what the user sees in their dashboard

Cause: the dashboard may show VAT-exclusive (net) amounts while the export
contains VAT-inclusive (gross) amounts, or cancelled orders are included in one
view but not the other.
Solution: ask the user to confirm (a) whether the dashboard shows gross or net,
and (b) how it handles cancelled orders. Recompute with matching logic.

### Duplicate rows in the export inflate order counts

Cause: some admin systems export one row per order item rather than one row per
order, so a single order for three movies appears as three rows.
Solution: check whether the data has an order ID column. If so, count distinct
order IDs for the order count metric rather than counting rows.

### No user ID column is present so retention metrics are unavailable

Cause: the export does not include a customer identifier, which is common in
GA4 standard exports or minimal admin setups.
Solution: report all available metrics and add a note: "Retention analysis
requires a unique customer or user ID column. Enable User-ID tracking in GA4
or export the customer ID from your order management system."

### Date range is very large (multi-year) and the report feels overwhelming

Cause: the user pasted or uploaded years of data without specifying a period.
Solution: ask the user to choose a focus period (last 30 days, last quarter,
specific year) and re-run the analysis scoped to that window. Offer to produce
a year-over-year summary as an alternative.
