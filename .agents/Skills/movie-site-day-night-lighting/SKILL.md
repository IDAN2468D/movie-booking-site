### Step 3: Generate the Time-Detection Hook or Utility

#### React/Next.js: custom hook

Produce a file at `src/hooks/useDayNight.js` (or `.ts` if the project uses TypeScript):

    import { useState, useEffect } from 'react';

    function getBand(hour) {
      if (hour >= 5 && hour < 8) return 'dawn';
      if (hour >= 8 && hour < 18) return 'day';
      if (hour >= 18 && hour < 21) return 'sunset';
      return 'night';
    }

    export function useDayNight() {
      const [band, setBand] = useState(() => getBand(new Date().getHours()));

      useEffect(() => {
        const tick = () => setBand(getBand(new Date().getHours()));
        // Re-check every minute so the theme transitions without a page reload
        const id = setInterval(tick, 60_000);
        return () => clearInterval(id);
      }, []);

      return band;
    }

#### Plain HTML/JS: utility function

Produce a `daynight.js` file at the project root or `/js/`:

    function getBand(hour) {
      if (hour >= 5 && hour < 8) return 'dawn';
      if (hour >= 8 && hour < 18) return 'day';
      if (hour >= 18 && hour < 21) return 'sunset';
      return 'night';
    }

    function applyDayNight() {
      const band = getBand(new Date().getHours());
      document.documentElement.setAttribute('data-band', band);
    }

    applyDayNight();
    setInterval(applyDayNight, 60_000);

## Gotchas

- **Flash of wrong band on load.** If the `data-band` attribute is applied after the first render (e.g., inside a React `useEffect`), there is a brief flash of unstyled or wrong-band colors. Mitigation: also call `document.documentElement.setAttribute('data-band', getBand(new Date().getHours()))` synchronously in a `<script>` tag placed in `<head>` before the stylesheet, or initialise the React state with the correct band immediately (as shown in the hook using the initialiser function form `useState(() => getBand(...))`).
- **Server-Side Rendering (Next.js SSR/SSG).** On the server, `new Date().getHours()` returns the server's time zone, which may differ from the user's local time. Always compute the band on the client side. Mark the provider component with `'use client'` and skip SSR hydration of the band attribute to avoid a mismatch warning.
- **User in a different time zone.** The feature uses `new Date().getHours()`, which is the user's LOCAL clock, so it works correctly even for visitors outside Israel. No time-zone conversion is needed.
- **CSS transition on `background-image` (gradients).** Browsers cannot smoothly transition between two `linear-gradient()` values on the `background` property. If the transition looks abrupt, use a pseudo-element overlay or transition `opacity` of a stacked gradient instead. The `bandShift` animation in Step 6 uses `opacity` as a workaround.
- **BiDi mixed content.** The movie site likely shows Hebrew titles alongside English movie titles and Latin numbers. Hebrew flows RTL, English flows LTR. Wrap English/Latin strings such as movie IDs or runtime in `<span dir="ltr">...</span>` to prevent visual reordering, especially in the night band where low contrast amplifies rendering glitches.
- **Tailwind v3 vs v4 variant syntax.** In Tailwind v3, custom variants are added via a `plugin()` call in `tailwind.config.js`. In v4, they are declared with `@custom-variant` in CSS. Confirm the version before generating config code.

## Troubleshooting

### Problem: The background does not change when I simulate a different band in the console

Cause: The CSS variables are scoped to `:root[data-band="..."]` but the `data-band` attribute is being set on a child element (e.g., `<main>`) rather than on `<html>` (`:root`).

Solution: Ensure the code calls `document.documentElement.setAttribute('data-band', band)` (not `document.body` or a component root). Verify in DevTools by inspecting the `<html>` element and confirming the `data-band` attribute is present.

### Problem: Colors flash back to default on every page navigation in Next.js

Cause: The `DayNightProvider` is mounted inside a page component, so it unmounts and remounts on navigation, causing a brief flash before the `useEffect` fires again.

Solution: Move the `DayNightProvider` (or the raw `useEffect` that sets `data-band`) into `app/layout.tsx` (App Router) or `pages/_app.tsx` (Pages Router) so it persists across page navigations without remounting.

### Problem: TypeScript error "Cannot find module '../hooks/useDayNight'"

Cause: The hook file was created with a `.js` extension in a TypeScript project that has `"allowJs": false` in `tsconfig.json`.

Solution: Rename the file to `useDayNight.ts` and ensure the return type is typed: `export function useDayNight(): 'dawn' | 'day' | 'sunset' | 'night'`.

### Problem: The gradient looks wrong or the wrong band is active

Cause: The time comparison uses strict integer hours, so a user opening the site at exactly 18:00:00 may land in either `day` or `sunset` depending on millisecond timing.

Solution: The `getBand` function uses `>=` for the lower bound and `<` for the upper bound consistently, so 18:00 maps to `sunset` as intended. If the band still seems wrong, log `new Date().getHours()` in the console to verify the local clock hour and compare it to the band table in Step 2.
